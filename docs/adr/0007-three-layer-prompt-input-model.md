# 商品图 prompt 采用三层分离输入模型

## Status

Accepted — 2026-07-XX

## Context

商品图自动生成器的 prompt 最终需要三个不同性质的输入来源组合而成：

1. **目标产品事实（Target Product Facts）** — 自有产品的真实参数、功能、配件和限制，来自已确认的产品资料版本。它是生成图不能违背的事实边界。
2. **素材事实（Source Material Facts）** — 从 ASIN 商品详情或图片表达来源中提取的可参考商品信息、卖点和兼容声明。它默认代表竞品或参考来源，不是自有产品的真实参数。
3. **图片表达结构（Image Expression Structure）** — 从图片 URL 经多模态 LLM 分析后提取的视觉 brief，描述场景、构图、风格、文案布局和生成约束。它提供画面语言但不提供产品事实。

三种来源的参与规则不同：目标产品事实默认参与，素材事实默认不参与需用户勾选，图片表达结构由用户选择一个参与。

初始实现将三类信息全部混存在 `AmazonImageTask.productFactsJson` 字段中，前端通过一个 JSON 编辑器让用户手工编辑。这种方式无法机械区分"哪个字段来自产品资料，哪个字段来自素材分析"，也缺乏"默认参与/不参与"的规则引擎。

## Constraints

- 最终 prompt 不能包含与自有产品相矛盾的事实
- 素材事实的引入必须经过用户显式确认，避免无意中把竞品卖点当作自有产品卖点
- 图片表达结构是只读分析产物，不在该层级编辑
- 生成记录中需要保存当时使用的三层输入的快照，用于复盘

## Considered Options

### 1. 合并输入法（拒绝）

保持当前设计，`productFactsJson` 一个字段存所有信息，前端 JSON 编辑器自由编辑，用户自行辨别哪些字段来自产品资料、哪些来自素材。

- **优点**：零改造成本
- **缺点**：用户容易不自觉地保留竞品卖点，生成误导图；无法自动判断一个字段是"自有事实"还是"素材参考"；生成记录无法追溯 prompt 中每个字段的来源
- **拒绝原因**：这是 PRD 明确禁止的做法（见 _Avoid_: 与 **素材事实** 混用），且无法接受法律合规风险（Amazon 商品图的误导声明可能触发下架）

### 2. 三层分离 + 参与规则（选定）

`AmazonImageTask` 实体中新增三个独立 JSON 字段（或关联实体）：

| 字段 | 内容 | 是否参与 prompt |
|------|------|----------------|
| `productFactsJson` | 来自产品资料版本的事实 | ✅ 默认参与，系统按图片类型自动选择相关字段 |
| `imageExpressionJson` | 来自多模态分析的视觉结构 | ✅ 用户选择一个参与 |
| `sourceMaterialFactsJson` | 来自 ASIN/URL 分析的事实 | ❌ 默认不参与，用户勾选后才加入 |

Prompt 生成时按规则组合：`imageExpression + productFacts + userCheckedMaterialFacts`

- **优点**：来源清晰可追溯；默认不参与机制避免素材事实静默进入 prompt；生成记录保存三层快照便于复盘
- **缺点**：新增一个字段到实体（后端成本低）；前端需要多一个勾选素材事实的 UI 组件

## Decision

采用三层分离方案。`AmazonImageTask` 新增 `imageExpressionJson` 和 `sourceMaterialFactsJson` 字段，与现有的 `productFactsJson` 并列。

Prompt 生成逻辑改为三层组合引擎，显式处理参与规则。

## Consequences

- **正面**：素材事实必须经用户勾选才进入 prompt，降低法律风险；每层快照独立保存，复盘时可以追溯到"当时用的哪个图片表达结构、勾选了哪些素材事实"
- **负面**：前端 wizard 的 prompt 步骤需要增加三层组合的预览区和素材事实勾选组件；后端 prompt 组合逻辑需要处理三层字段的 JSON merge
- **风险**：如果后续规则配置中心实现（P3），参与规则需要从写死改为可配置。当前写死规则应与三层字段一一对应，便于未来抽取
