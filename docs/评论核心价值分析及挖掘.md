这个项目的核心不应该是“统计好评和差评”，而应该是建立一套：

> **评论原文 → 用户问题 → 使用场景 → 产品模块 → 严重程度 → 改进动作 → 商业价值**

的闭环分析系统。

对于 Car Stereo 类目，建议把评论分析拆成 **8 个核心层级、30+ 个分析维度**。

------

# 一、评论基础数据层

首先保留评论原始字段，后续所有分析都可以回溯。

建议每条评论包含：

```text
ASIN
品牌
产品型号
评论ID
评论标题
评论正文
评分
评论日期
是否Verified Purchase
是否Vine
Helpful数量
评论者名称或匿名ID
评论国家/站点
产品变体
抓取时间
```

额外生成以下 AI 字段：

```text
评论语言
翻译文本
情感倾向
评论主题
产品模块
问题标签
使用场景
车辆信息
安装方式
问题严重程度
购买阶段
可执行建议
分析置信度
```

不要只保存 AI 总结，必须保留评论原文以及评论与分析结果之间的映射关系。

# 二、整体口碑分析

这是 HTML 报表首页需要展示的内容。

## 1. 评分分布

分析：

- 1～5 星评论数量和占比
- 平均评分
- 中位数评分
- 各 ASIN 评分对比
- 不同时间段评分变化
- Verified Purchase 与非 Verified 评论差异
- Vine 与普通评论差异

特别需要关注：

- 近期评分是否下降
- 低星评论占比是否突然增加
- 某个产品版本更新后评分是否发生变化

平均评分可能掩盖问题。例如一个产品平均 4.2 星，但最近三个月可能已经下降到 3.6 星。

## 2. 情感分析

不要只分正面、负面、中性，建议进一步拆为：

- 强烈正面
- 一般正面
- 中性描述
- 一般负面
- 强烈负面
- 正负混合

Car Stereo 评论经常是混合型：

> Screen looks great and CarPlay works well, but the microphone is terrible.

这条评论必须拆成：

```text
屏幕：正面
CarPlay：正面
麦克风：强烈负面
整体评分：混合
```

不能只把整条评论标成“中性”或“负面”。

# 三、产品模块分析

这是整份报告最重要的分析维度。

建议建立 Car Stereo 专属产品模块分类体系。

## 1. 硬件性能

包括：

- 开机速度
- 系统运行速度
- 页面切换流畅度
- RAM 是否够用
- 存储空间
- 发热
- 死机
- 自动重启
- 黑屏
- 触摸延迟
- 触摸失灵
- 按键反馈
- 旋钮手感
- USB 接口稳定性
- 线束或接口松动

输出示例：

| 问题     | 提及次数 | 负面率 | 严重度 | 主要表现                |
| -------- | -------- | ------ | ------ | ----------------------- |
| 开机慢   | 86       | 78%    | 中     | 冷启动需要30秒以上      |
| 随机重启 | 42       | 96%    | 高     | 导航或CarPlay过程中重启 |
| 触摸延迟 | 31       | 84%    | 中     | 点击后响应延迟          |

## 2. 屏幕显示

包括：

- 屏幕清晰度
- 分辨率
- 色彩表现
- QLED 显示效果
- 屏幕亮度
- 阳光下可视性
- 夜间是否刺眼
- 自动亮度
- 可视角度
- 反光
- 屏幕尺寸
- 屏幕边框
- 屏幕是否出现坏点、闪屏、黑屏

这部分可以直接指导：

- 屏幕硬件升级
- UI 主题调整
- Listing 卖点排序
- 产品图视觉表达

## 3. CarPlay / Android Auto

需要分别分析，不要混在一个标签里。

### CarPlay

- Wireless CarPlay 连接速度
- 首次配对难度
- 自动重连
- 断连
- 音频卡顿
- 延迟
- 通话质量
- Siri 唤醒
- 地图显示
- 音乐播放
- 手机兼容性
- 有线 CarPlay 稳定性

### Android Auto

- 有线 Android Auto
- 无线 Android Auto
- Google Assistant
- 手机型号兼容性
- 自动连接
- 断连
- 黑屏
- 分辨率或界面比例异常
- 音频延迟

还应提取手机型号：

```text
iPhone 13
iPhone 15 Pro
Samsung Galaxy S24
Google Pixel 8
```

最终可以输出：

> iPhone 用户主要抱怨自动重连；Samsung 用户主要抱怨无线 Android Auto 断连。

这种结论比单纯说“连接问题较多”更有价值。

## 4. 蓝牙、Wi-Fi 与网络

分析：

- 蓝牙配对
- 蓝牙自动连接
- 蓝牙通话
- 蓝牙音乐
- Wi-Fi 连接
- 手机热点连接
- Wi-Fi 掉线
- 连接距离
- 音频延迟
- 多设备切换
- GPS 天线信号
- 定位漂移
- 定位速度

## 5. 音频体验

包括：

- 音质
- 音量
- 低音
- 高音
- 均衡器
- 声道
- 原车功放兼容
- 外接功放
- RCA 输出
- 底噪
- 电流声
- 爆音
- 左右声道异常
- 收音机信号
- AM/FM 接收
- 麦克风质量
- 通话回声
- 对方听不清
- 外置麦克风效果

建议把音频问题拆成：

```text
输入问题
输出问题
通话问题
收音问题
功放兼容问题
线路噪声问题
```

## 6. 倒车影像与摄像头

分析：

- 倒车摄像头安装
- 摄像头画质
- 夜视效果
- 倒车触发
- 延迟
- 黑屏
- 图像反转
- 辅助线
- 原车摄像头兼容
- 第三方摄像头兼容
- 摄像头供电问题

尤其要区分：

- 车机本体问题
- 摄像头问题
- 接线错误
- 说明书不清楚
- 车辆协议不兼容

否则容易把安装问题误判成产品缺陷。

## 7. 方向盘控制与车辆功能

包括：

- Steering Wheel Control
- SWC 学习
- CANBUS
- 原车按钮
- 原车功放
- 原车摄像头
- 车辆设置
- 空调信息
- 门灯信息
- 倒车触发
- ACC
- 照明线
- 原车 USB
- 原车天线

这一模块对专车专用 Car Stereo 特别重要。

## 8. 软件与系统

包括：

- Android 系统稳定性
- App 安装
- Google Play
- 软件兼容
- 系统更新
- 固件更新
- UI 易用性
- 多语言
- 时间设置
- 时区
- 保存设置
- 恢复出厂设置
- 休眠唤醒
- 冷启动
- 开机 Logo
- 分屏
- 导航软件
- 第三方 App 闪退

要单独识别：

```text
硬件缺陷
软件Bug
固件版本问题
用户不会设置
说明书缺失
第三方App问题
```

# 四、安装与适配分析

Car Stereo 类目中，安装相关评论往往比产品功能评论更有价值。

## 1. 车辆适配信息提取

从评论中提取：

- 汽车品牌
- 车型
- 年份
- 配置版本
- 是否带原厂功放
- 是否带 Bose / JBL 等音响
- 是否带原厂摄像头
- 是否带方向盘控制
- 是否需要额外转接线
- 是否需要切割仪表台

例如：

```text
Vehicle: Ford F-150
Year: 2012
Trim: XLT
Factory amplifier: Unknown
Fitment result: Partial fit
Issue: Mounting bracket holes do not align
```

## 2. 适配结果分类

建议分为：

- 完美适配
- 基本适配
- 需要轻微修改
- 需要额外配件
- 安装困难
- 不适配
- 车型信息不足，无法判断

## 3. 安装难度

分析：

- Plug and Play
- 需要专业安装
- 接线复杂
- 插头不匹配
- 线束定义错误
- 缺少转接线
- 缺少螺丝或支架
- 面框尺寸不合
- 安装说明不清晰
- 安装视频是否有帮助
- 安装耗时

建议提取评论中的安装时间：

```text
Under 30 minutes
30–60 minutes
1–2 hours
More than 2 hours
Professional installation required
```

## 4. 安装责任归因

这一项非常重要，应将问题归因到：

- 产品设计
- 配件缺失
- 说明书问题
- 用户接线错误
- 车辆版本差异
- Listing 适配声明不清
- 卖家提供了错误线束
- 安装人员技术问题
- 无法判断

这样才能避免团队收到差评后，错误地要求研发修改产品。

- 说明书缺失
- 线束错误

## 阶段三：安装

关注：

- 适配
- 接线
- 支架
- 面框
- CANBUS
- 安装说明

## 阶段四：首次配置

关注：

- 开机设置

# 六、问题严重程度与风险分析

不能只统计提及次数，因为高频问题不一定最严重。

建议从四个维度打分：

```text
问题频率
负面情绪强度
功能影响程度
退货或安全风险
```

可以建立一个问题优先级分数：

```text
Priority Score =
提及频率 × 25%
+ 负面率 × 20%
+ 严重度 × 25%
+ 退货关联度 × 20%
+ 近期增长率 × 10%
```

严重程度建议分为：

### P0：安全或车辆风险

例如：

- 行驶过程中黑屏
- 设备过热冒烟
- 电池亏电
- 倒车影像失效
- 接线短路
- 影响车辆原有功能

### P1：核心功能不可用

例如：

- 无法开机
- CarPlay 完全无法连接
- 无声音
- 随机重启
- 触摸失灵

### P2：影响体验但可继续使用

例如：

- 偶尔断连
- 麦克风音质差
- 开机较慢
- 屏幕反光
- 收音机信号弱

### P3：轻微体验或期望差异

例如：

- 图标不好看
- UI 不符合习惯
- 说明书字体小
- 包装不够精致

HTML 报表中应优先展示 P0、P1 问题，而不是单纯展示最高频词。

# 七、需求与卖点分析

评论不只是找问题，也要找用户真正认可的价值。

## 1. 正向卖点提取

例如：

- Screen is bright and clear
- Easy to install
- Wireless CarPlay connects quickly
- Looks factory installed
- Great value for money
- Responsive touchscreen
- Good customer support

输出：

- 卖点提及次数
- 正面率
- 对五星评价的贡献
- 对不同车型用户的贡献
- 是否值得放入标题、五点或副图

## 2. 隐性需求提取

用户可能不会直接说“我需要什么”，但会通过抱怨表达需求。

例如：

> Every time I start the truck, I need to reconnect my phone.

可转化为：

```text
用户需求：稳定自动重连
产品要求：点火后自动恢复无线CarPlay
Listing机会：强调Automatic Reconnection
测试场景：连续启动车辆20次
```

## 3. 未满足需求

重点分析：

- 用户希望但产品没有的功能
- 用户认为应该附送的配件
- 用户需要更详细的安装指导
- 用户想保留的原车功能
- 用户希望改善的软件设置

例如：

- 希望支持自定义开机 Logo
- 希望提供更好的外置麦克风
- 希望附带安装视频
- 希望支持原车 USB
- 希望提供不同车型的线束选项

# 八、退货、客服与商业影响分析

## 1. 退货意图

识别评论中的：

- Returned
- Sending it back
- Requested refund
- Replacement
- Waste of money
- Do not buy

输出：

- 退货意图评论占比
- 退货原因排名
- 与产品模块的关系
- 与车型的关系
- 与安装问题的关系

## 2. 客服体验

分析：

- 响应速度
- 是否解决问题
- 技术支持能力
- 是否主动提供固件
- 是否提供换货
- 沟通是否清楚
- 用户最终是否满意

建议区分：

```text
产品有问题，但客服解决了
产品有问题，客服未解决
用户安装错误，客服协助解决
客服体验推动用户修改评分
```

## 3. Helpful 评论分析

Helpful 数量高的评论通常更能代表买家的核心担忧。

应单独输出：

- 最有帮助的正面评论
- 最有帮助的负面评论
- Helpful 高评论的主要主题
- 对购买决策影响最大的疑虑

# 九、竞品 ASIN 对比分析

给定多个 ASIN 时，不要简单地并排展示评分。

建议建立统一产品模块，对各 ASIN 横向比较：

| 分析模块       | ASIN A | ASIN B | ASIN C |
| -------------- | ------ | ------ | ------ |
| 安装正面率     | 72%    | 48%    | 65%    |
| CarPlay负面率  | 14%    | 27%    | 11%    |
| 麦克风负面率   | 31%    | 18%    | 22%    |
| 屏幕正面率     | 81%    | 76%    | 69%    |
| 随机重启提及率 | 4%     | 12%    | 6%     |

进一步输出四种结论：

### 竞品优势

竞品得到大量认可，而自己的产品没有体现的能力。

### 竞品弱点

竞品高频差评，可作为自己产品的突破口。

### 类目共性问题

多个 ASIN 都存在的问题，例如：

- 麦克风质量差
- 安装说明不清楚
- 无线连接偶尔断开

这类问题往往是最好的产品升级机会。

### 差异化机会

例如：

> 大多数竞品都强调屏幕和 CarPlay，但用户对原车摄像头兼容和技术支持更不满意。

那么自己的产品可以重点建立：

```text
更明确的适配体系
更完整的线束配置
车型专属安装视频
更快的售后技术支持
```

# 十、时间趋势分析

评论分析必须加入时间维度。

建议展示：

- 每月评论量
- 每月平均星级
- 每月负面评论率
- 每个问题的月度趋势
- 新问题出现时间
- 问题是否持续恶化
- 固件或硬件版本更新前后变化

重点识别：

- 新出现问题
- 快速增长问题
- 已改善问题
- 长期未解决问题
- 季节性问题

例如：

> “无线 CarPlay 断连”过去六个月一直稳定，但最近两个月提及率从 8% 上升至 21%。

这种趋势比总量更值得立即关注。

------

# 十一、建议增加“事实可信度”分析

Amazon 评论中存在信息不足、误用和错误归因。

因此每个结论应增加置信度：

- 高置信度：评论描述清楚，包含车型、操作过程和结果
- 中置信度：问题明确，但缺少环境信息
- 低置信度：只有一句抱怨，无法确认原因

还可以识别：

- 极短评论
- 重复文本
- 疑似模板化内容
- 评论与星级不一致
- 评论内容与产品无关
- 缺少实际使用信息

低置信度评论可以参与统计，但不应该直接驱动产品修改。

# 十四、建议采用的标签体系

建议使用多标签，而不是一条评论只分配一个分类。

一条评论可以同时拥有：

```text
产品模块：CarPlay、Microphone
情感：CarPlay正面、Microphone负面
问题：通话声音小
使用阶段：日常使用
车辆：2013 Ford F-150
严重程度：P2
结果：继续使用
售后：未联系
建议部门：硬件、客服
```

推荐标签层级：

```text
一级：产品模块
二级：功能或组件
三级：具体问题
四级：问题表现或根因
```

例如：

```text
Connectivity
└── Wireless CarPlay
    └── Auto Reconnection
        └── Fails after vehicle restart
```

# 最关键的设计原则

最终系统不能只输出：

> “CarPlay 是评论中最常提到的问题。”

而应该输出：

> 最近六个月，Wireless CarPlay 自动重连失败在 1～3 星评论中出现 68 次，其中 43 次发生在车辆重新启动后，主要涉及 iPhone 用户。该问题与退货表达高度相关，建议将其列为 P1。短期应提供固件修复和重新配对指南，中期应增加连续点火重连测试。Listing 中暂时避免强调“seamless automatic connection”。

这样的结论才真正能支持产品优化、研发排期、客服话术和 Amazon Listing 调整。
